TARSUS FINDER 4.8.0 — CHECKLIST UJI PENGGUNA

PENTING
Paket ini disiapkan sebagai build uji terpadu berdasarkan source ZIP yang diberikan. Pemeriksaan sintaks JavaScript, JSON manifest, dan service worker telah dilakukan. Pengujian end-to-end pada perangkat Android asli belum dapat diklaim selesai; mohon jalankan checklist berikut setelah deploy ke GitHub Pages.

A. BOOT, LOGIN, DAN REFRESH
[ ] Logo boot terlihat jelas dan tidak terpotong.
[ ] Boot beralih ke login tanpa layar kosong.
[ ] Kartu login tidak memenuhi seluruh layar portrait.
[ ] Coba login prototipe sesuai kredensial demo yang tertulis di app.js (jangan gunakan password kerja).
[ ] Setelah login, animasi masuk singkat dan halaman beranda tampil.
[ ] Refresh saat login: halaman login tetap muncul.
[ ] Refresh saat beranda: aplikasi kembali normal, tidak blank.
[ ] Refresh saat halaman Cari Tarif, Favorit, Riwayat, Pusat Bantuan, Tentang, dan Pengaturan.
[ ] Matikan koneksi sementara: status database gagal tampil dengan jelas; hidupkan koneksi lagi dan pastikan pemuatan dicoba ulang.
[ ] Setelah deploy, jika aset lama tetap muncul, tutup tab/app lalu buka ulang atau bersihkan data situs/cache PWA satu kali.

B. BERANDA DAN NAVIGASI
[ ] Sapaan pagi/siang/sore/malam sesuai jam perangkat dan nama akun tampil.
[ ] Banner bisa digeser manual dan berpindah otomatis sekitar 4 detik.
[ ] Menu pintasan memiliki susunan yang nyaman pada lebar 320, 360, 390, dan 430 px.
[ ] Panel navigasi terbuka/tutup, semua menu menuju halaman yang benar.
[ ] Badge Favorit berubah ketika item disimpan/dihapus.

C. PENCARIAN TARIF
[ ] Cari relasi dengan nama stasiun yang valid.
[ ] Coba stasiun asal dan tujuan sama: harus ditolak dengan pesan jelas.
[ ] Coba rute yang tidak tersedia: empty state tampil.
[ ] Tukar stasiun dan cari kembali.
[ ] Periksa nama kereta, relasi yang cocok, dan tarif Eksekutif/Bisnis/Ekonomi terhadap Google Sheets sumber.
[ ] Buka/tutup tarif alternatif; pastikan kartu alternatif tampil lebih ringkas.
[ ] Tombol salin tarif menyalin informasi yang benar.
[ ] Pastikan perubahan visual tidak mengubah aturan arah/relasi tarif dari data.js.

D. TARIF PER KERETA DAN DIREKTORI STASIUN
[ ] Daftar kereta tidak terbuka otomatis ketika halaman pertama kali dibuka.
[ ] Pencarian nama kereta memunculkan hasil dan pemilihan kereta menampilkan relasi.
[ ] Tombol Tampilkan Semua Kereta membuka/menutup daftar.
[ ] Pencarian stasiun dan filter Daop/Divre bekerja bersama.

E. FAVORIT, RIWAYAT, DAN DIALOG
[ ] Simpan tarif ke Favorit dari halaman yang mendukung ikon favorit.
[ ] Favorit tetap ada setelah refresh pada browser/perangkat yang sama.
[ ] Hapus satu favorit dan hapus riwayat melalui dialog aplikasi.
[ ] Batal pada dialog tidak mengubah data.
[ ] Hapus data lokal melalui Pengaturan memperbarui badge, Favorit, Riwayat, dan beranda.

F. PUSAT BANTUAN DAN TOUR
[ ] FAQ dapat dibuka/tutup.
[ ] Email pengembang membuka aplikasi email dengan alamat tujuan yang benar.
[ ] Tour seluruh aplikasi dan tour pencarian berjalan, progres berubah, tombol Kembali/Lanjut/Lewati/Selesai berfungsi.
[ ] Spotlight tour berada di sekitar fitur yang sedang dijelaskan dan tidak membuat tombol tour tertutup.
[ ] Tour pengguna baru muncul setelah login prototipe pertama pada perangkat tersebut.

G. TENTANG, PENGATURAN, DAN KELUAR
[ ] Foto pengembang berbentuk bulat; Instagram membuka profil yang ditentukan.
[ ] Ganti tautan LinkedIn placeholder dengan URL profil yang benar sebelum rilis.
[ ] Tema terang/gelap dan ukuran teks tersimpan setelah refresh.
[ ] Logout mengakhiri sesi UI dan kembali ke login.
[ ] Keluar aplikasi mencoba menutup jendela; jika browser melarangnya, pesan fallback muncul. Browser web tidak selalu mengizinkan tab ditutup oleh JavaScript.

BATASAN YANG HARUS DITUNTASKAN SEBELUM PEMAKAIAN OPERASIONAL
1. Login/registrasi masih prototipe sisi browser dan bukan autentikasi aman. Kredensial demo dapat dibaca dari app.js. Jangan gunakan untuk melindungi data sensitif. Integrasikan backend autentikasi sebelum rilis operasional.
2. Pendaftaran saat ini mengarahkan pengguna mengajukan akses melalui email, bukan membuat akun otomatis.
3. Penguncian portrait diminta melalui manifest dan API pada mode standalone, tetapi browser tertentu dapat mengabaikannya.
4. Konten poster banner masih berupa materi yang sudah ada di folder assets; ganti dengan pengumuman resmi yang valid sebelum dipakai.
5. Ganti URL LinkedIn placeholder jika ingin menautkan profil pribadi pengembang.
